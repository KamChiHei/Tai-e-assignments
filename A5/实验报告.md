## 二、实验目的

本次实验的目标是在 Tai-e 框架中实现 Java 的非上下文敏感指针分析，并在指针分析过程中实时构建调用图。通过本实验，需要理解并实现以下内容：

1. 使用创建点抽象对堆对象建模。
2. 通过指针流图表示对象在不同指针之间的传播关系。
3. 使用 WorkList 算法迭代传播 points-to set。
4. 支持局部变量、实例字段、静态字段和数组索引四类指针。
5. 处理实例方法调用和静态方法调用，并根据指针分析结果实时构建更精确的调用图。

## 三、实验原理

指针分析的核心任务是计算程序中每个指针可能指向的抽象对象集合，即 points-to set。本实验采用上下文不敏感分析，因此同一个变量、字段或方法在不同调用上下文下不会被区分；同时采用创建点抽象，每条 `new` 语句对应一个抽象对象。

分析过程以指针流图为基础。指针流图中的节点表示不同种类的指针，边表示对象可能沿着该方向传播。例如赋值语句 `x = y` 会产生从 `y` 到 `x` 的指针流边；静态字段读取 `x = T.f` 会产生从静态字段 `T.f` 到变量 `x` 的边；实例字段和数组访问则需要等到 base 变量发现新的接收对象后，再为相应对象上的字段或数组索引建立指针流边。

WorkList 算法用于驱动传播。每次从 WorkList 中取出一个指针和待传播对象集合，将真正新增的对象加入该指针的 points-to set，并把新增部分继续传播给该指针流图的后继节点。这样可以避免重复传播已经处理过的对象，提高迭代效率。

调用图构建与指针分析交织进行。对于静态调用，可以直接解析目标方法；对于实例调用，需要在接收者变量发现新的对象后，根据该对象的实际类型解析被调用方法，并添加调用边、传播实参、传播返回值以及向被调用方法的 `this` 变量传播接收对象。

## 四、关键类与数据结构

- `PointerFlowGraph`：维护指针流图，并提供获取变量指针、静态字段指针、实例字段指针和数组索引指针的接口。
- `Pointer`：指针流图节点的抽象父类，每个指针都拥有自己的 points-to set。
- `PointsToSet`：保存一组抽象对象 `Obj`，表示某个指针可能指向的对象集合。
- `WorkList`：保存待处理的传播任务，每个任务由一个目标指针和一组待传播对象组成。
- `HeapModel`：根据 `New` 语句生成抽象对象，实现创建点抽象。
- `DefaultCallGraph`：保存分析过程中发现的可达方法和调用边。
- `Var`：表示 Tai-e IR 中的变量，并提供 `getStoreFields()`、`getLoadFields()`、`getStoreArrays()`、`getLoadArrays()`、`getInvokes()` 等接口，便于在变量 points-to set 更新时处理相关语句。

## 五、实现内容

### 1. 初始化与可达方法处理

在 `initialize()` 中创建 WorkList、PointerFlowGraph、CallGraph 和语句访问器，并从程序入口 `main` 方法开始分析。`addReachable(JMethod method)` 首先通过 `callGraph.addReachableMethod(method)` 做去重，避免重复扫描同一个方法；如果方法不是抽象方法，则遍历其 IR 中的每条语句并交给 `StmtProcessor` 处理。

该部分对应实现：

- 初始化入口方法：`Solver.java` 第 84-94 行
- 处理新可达方法：`Solver.java` 第 99-107 行

### 2. 语句访问器处理初始约束

`StmtProcessor` 使用访问者模式处理不同 IR 语句：

- `New`：通过 `heapModel.getObj(stmt)` 得到创建点对应的抽象对象，并把该对象加入左值变量的 WorkList 条目。
- `Copy`：对 `x = y` 添加 `y -> x` 的 PFG 边。
- 静态字段 store：对 `T.f = y` 添加 `y -> T.f` 的 PFG 边。
- 静态字段 load：对 `x = T.f` 添加 `T.f -> x` 的 PFG 边。
- 静态方法调用：直接解析 callee，添加调用图边，标记 callee 可达，并建立实参到形参、返回变量到调用结果变量的 PFG 边。

数组访问和实例字段访问没有在初始扫描时直接建立完整约束，因为它们依赖 base 变量实际指向的对象，需要在变量 points-to set 发生变化时动态处理。

该部分对应实现：

- `New` 与 `Copy`：`Solver.java` 第 113-125 行
- 静态字段读写：`Solver.java` 第 127-145 行
- 静态调用：`Solver.java` 第 157-180 行

### 3. 添加 PFG 边

`addPFGEdge(Pointer source, Pointer target)` 用于向指针流图中添加从 source 到 target 的边。如果这条边是新边，并且 source 当前已经有非空 points-to set，则立即把 source 已知对象加入 target 的 WorkList 条目中。这样可以保证后加入的边也能收到之前已经发现的对象，不会漏传播。

该部分对应实现：`Solver.java` 第 186-190 行。

### 4. WorkList 主循环

`analyze()` 是指针分析的主循环。每次从 WorkList 取出一个条目，调用 `propagate()` 传播对象集合，并得到真正新增的 `delta`。如果当前更新的指针是变量指针 `VarPtr`，则对 `delta` 中每个新对象触发以下处理：

- 实例字段 store：对 `x.f = y` 添加 `y -> o.f` 的 PFG 边。
- 实例字段 load：对 `y = x.f` 添加 `o.f -> y` 的 PFG 边。
- 数组 store：对 `x[i] = y` 添加 `y -> o[*]` 的 PFG 边。
- 数组 load：对 `y = x[i]` 添加 `o[*] -> y` 的 PFG 边。
- 实例方法调用：调用 `processCall(var, obj)` 解析并处理以该变量为 receiver 的调用点。

该部分对应实现：`Solver.java` 第 195-226 行。

### 5. 差分传播

`propagate(Pointer pointer, PointsToSet pointsToSet)` 负责把传入对象集合加入目标指针的 points-to set。实现中只收集真正新增的对象作为 `delta`，再将 `delta` 传播给当前指针在 PFG 中的所有后继节点。这样可以避免重复传播，保证算法能够在有限步内达到不动点。

该部分对应实现：`Solver.java` 第 232-245 行。

### 6. 实例方法调用处理

`processCall(Var var, Obj recv)` 在 receiver 变量发现新对象时触发。对该变量关联的每个实例调用点，首先用 `resolveCallee(recv, callSite)` 根据接收对象类型解析目标方法，然后添加调用图边。如果该调用边是新发现的，则将 callee 标记为可达并扫描其 IR。

随后，分析会把接收对象传给 callee 的 `this` 变量，把调用点实参传播给 callee 形参，并把 callee 的返回变量传播给调用点左侧结果变量。这保证了方法调用两端的数据流能够被纳入同一个指针分析求解过程。

该部分对应实现：`Solver.java` 第 253-276 行。

## 七、实验总结

通过本次实验，我进一步理解了指针分析中“约束生成”和“约束求解”之间的关系。初始扫描阶段负责为 `new`、赋值、静态字段和静态调用生成基础约束；WorkList 主循环则在 points-to set 不断增长的过程中动态补充实例字段、数组和实例调用相关的约束。

本实验中较关键的一点是差分传播。只有当某个指针发现新对象时，才需要继续处理该对象引发的字段访问、数组访问和方法调用；否则重复传播不仅浪费时间，也容易让实现逻辑变得混乱。另一个关键点是调用图与指针分析的互相依赖：实例调用的目标方法依赖 receiver 的 points-to set，而新发现的调用边又会引入新的可达方法和新的数据流约束。

最终实现完成了非上下文敏感指针分析的核心流程，并支持局部变量、实例字段、静态字段、数组索引、静态调用和实例调用等主要 Java 指针相关特性。
